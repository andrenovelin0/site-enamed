## User Story

**Como** desenvolvedor consumindo o design system,
**eu quero** um componente `<Button>` React tipado com todas as 7 variantes oficiais e 3 tamanhos,
**para que** eu possa usar a marca EMR de forma consistente em CTAs, formulários e cards, sem repetir classes Tailwind nem inventar variações fora do manual.

## Contexto

A story 001.1 (tokens DS) entregou em `src/app/globals.css` as classes utilitárias `.btn-primary`, `.btn-secondary`, `.btn-accent`, `.btn-pill`, `.btn-urgency`. A Home (`src/app/page.tsx`) já consome essas classes diretamente, mas isso não escala — precisamos do componente React para:

1. Garantir tipagem TypeScript
2. Padronizar acessibilidade (focus ring, aria, min touch target)
3. Permitir composição com Next `<Link>` via `asChild`
4. Suportar estados `loading` e `disabled` consistentes
5. Aceitar ícones Material Symbols sem hack

Specs detalhados em `docs/design-system/components-spec.md` §`<Button>`.

⚠️ **Regra crítica do manual (p29):** variante `urgency` (vermelho `#E64444`) é **apenas para campanhas editoriais de últimos dias**. NÃO usar como botão de erro de form. Documentar inline.

⚠️ **AGENTS.md:** este projeto usa Next.js 16.2.6 com breaking changes. Antes de codar, consultar `node_modules/next/dist/docs/` para:
- `app/link` (uso atual de `<Link>` do Next)
- `client-components` (quando precisa de `"use client"`)

## Acceptance Criteria

1. **AC1 — Componente exportado:** `src/components/ui/button.tsx` exporta `Button` e o tipo `ButtonProps`. Re-exportado em `src/components/ui/index.ts` se este arquivo existir.

2. **AC2 — 7 variantes implementadas e visualmente fiéis às classes existentes em `globals.css`:**
   - `primary` → `.btn-primary` (brand-800 / white)
   - `secondary` → `.btn-secondary` (white / brand-800 com border 1.5px)
   - `accent` → `.btn-accent` (brand-500 / brand-950)
   - `outline` → variante NOVA (transparent / brand-800, sem fundo)
   - `ghost` → variante NOVA (transparent / brand-800, sem border)
   - `pill` → `.btn-pill` (brand-800 / white, radius-pill, uppercase)
   - `urgency` → `.btn-urgency` (coral-500 / white, radius-pill, uppercase)

3. **AC3 — 3 tamanhos implementados** (`sm` / `md` / `lg`) conforme spec §Sizes. `md` é o default. Mobile: `min-height: 44px` em todos.

4. **AC4 — Suporte a ícones:** props `iconLeft` e `iconRight` aceitam `ReactNode`. Quando presentes, `gap: 0.5rem`. Tamanho do ícone deriva do tamanho do botão (sm→16, md→18, lg→20).

5. **AC5 — Estado loading:** prop `loading` (boolean). Quando `true`:
   - Botão fica `aria-busy="true"`
   - Conteúdo é substituído por spinner com `role="status"` + screen-reader-only "Carregando…"
   - Botão fica não-clicável (`pointer-events: none`)

6. **AC6 — Estado disabled:** prop `disabled` (boolean) ou estado nativo `<button disabled>`. Visual: `opacity: 0.5`, `cursor: not-allowed`, sem hover.

7. **AC7 — `asChild` para Next Link:** prop `asChild` (boolean). Quando `true`, o componente renderiza o `children` (esperado ser um `<Link>` do Next) injetando classes e props ao child. Usar padrão Radix Slot — instalar `@radix-ui/react-slot` como dependência.

8. **AC8 — Acessibilidade:**
   - `:focus-visible` mostra `var(--shadow-focus)` (já em globals.css)
   - Icon-only (sem `children` ou children vazio) requer `aria-label` em runtime; sem o aria-label, console.warn em dev.
   - `prefers-reduced-motion` respeitado (já em globals.css)

9. **AC9 — Refator da Home:** `src/app/page.tsx` migra os atuais usos de `className="btn-*"` para `<Button variant="…">`. Comportamento e aparência idênticos.

10. **AC10 — Galeria visual:** criar `src/app/design-system/page.tsx` (rota dev-only, **NÃO** indexada — adicionar a `robots.ts` se necessário) renderizando uma matriz de todas as 7 variantes × 3 tamanhos × estados (default/hover/disabled/loading). Servirá como página de validação visual e snapshot para futuras regressões.

11. **AC11 — Validação manual no browser:** `preview_screenshot` da nova rota `/design-system` anexado ao commit; `preview_console_logs` sem erros nem warnings; Home não regrediu (compare snapshot atual com o pós-refator).

12. **AC12 — Tipagem estrita:** zero `any`. Props extendem `React.ButtonHTMLAttributes<HTMLButtonElement>` para passthrough de `type`, `onClick`, etc.

13. **AC13 — Sem regressão de build:** `pnpm build` (ou `npm run build`) passa sem erros. ESLint limpo (`pnpm lint`).

## Dev Notes

### Estrutura sugerida do componente

```tsx
// src/components/ui/button.tsx
"use client";

import { Slot } from "@radix-ui/react-slot";
import { forwardRef, type ButtonHTMLAttributes, type ReactNode } from "react";
import { cn } from "@/lib/cn";

export type ButtonVariant =
  | "primary"
  | "secondary"
  | "accent"
  | "outline"
  | "ghost"
  | "pill"
  | "urgency";

export type ButtonSize = "sm" | "md" | "lg";

export interface ButtonProps
  extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: ButtonVariant;
  size?: ButtonSize;
  asChild?: boolean;
  loading?: boolean;
  iconLeft?: ReactNode;
  iconRight?: ReactNode;
}

const VARIANT_CLASSES: Record<ButtonVariant, string> = {
  primary:   "btn-primary",
  secondary: "btn-secondary",
  accent:    "btn-accent",
  outline:   "...", // definir Tailwind utilities ou nova classe
  ghost:     "...",
  pill:      "btn-pill",
  urgency:   "btn-urgency",
};

const SIZE_CLASSES: Record<ButtonSize, string> = {
  sm: "px-4 py-2 text-sm min-h-9",
  md: "", // default já no .btn-*
  lg: "px-8 py-4 text-base min-h-13",
};

export const Button = forwardRef<HTMLButtonElement, ButtonProps>(
  ({ variant = "primary", size = "md", asChild, loading, iconLeft, iconRight, className, children, disabled, ...rest }, ref) => {
    const Component = asChild ? Slot : "button";
    return (
      <Component
        ref={ref}
        className={cn(VARIANT_CLASSES[variant], SIZE_CLASSES[size], className)}
        disabled={disabled || loading}
        aria-busy={loading || undefined}
        {...rest}
      >
        {loading ? <Spinner /> : (
          <>
            {iconLeft}
            {children}
            {iconRight}
          </>
        )}
      </Component>
    );
  }
);
Button.displayName = "Button";
```

> ⚠️ Pseudo-código. Validar **antes** que `Slot` do Radix funciona com Next 16 (testar passando `<Link href>` como child). Se houver issue, fallback é renderizar `<a>` quando detectar `href` na prop manualmente.

### Helper `cn()`

```ts
// src/lib/cn.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

### Debug Log References

- Bug encontrado durante implementação: `isValidElement(children)` retornava `false` quando Server Component (`page.tsx`) passa `<Link>` para Client Component (`Button`) como children. Em React 19 + RSC, children atravessando boundary Server→Client é um payload RSC opaco que não passa em `isValidElement`. Solução: removi a validação estrita; deleguei ao Radix Slot, que faz cloning robusto sem precisar do check.
- Tradeoff registrado: ao usar `asChild`, `iconLeft`/`iconRight` não são injetados automaticamente dentro do child (pelo `<Slot>` apenas clonar o filho). Padrão: quem usa asChild deve incluir os ícones manualmente no `<Link>` filho. Documentado nos componentes da galeria.
